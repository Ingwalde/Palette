# ПОЧАТОК ПРОМТУ

Ти працюєш над релізом **Palette v5.0** у репозиторії `Ingwalde/Palette`.

Тема релізу: **«Палітра — це продукт»**. У версіях 4.8.x усе зусилля йшло в інфраструктуру
(безпека, CI, спостережуваність, доступність). Інтерфейс за той час відстав: каталог палітр не
можна пошерити, окремої палітри як сутності в UI не існує взагалі, а тексти на сторінках
описують власну архітектуру замість продукту. v5.0 це виправляє.

## Контекст репозиторію

- `frontend-react/` — Vite + React 19 + TypeScript (strict), React Router, TanStack Query,
  **vanilla-extract** для стилів (жодного CSS-файлу, лише `*.css.ts`), Vitest + Testing Library,
  Playwright + axe-core.
- `backend/` — FastAPI + PostgreSQL (async SQLAlchemy), Redis для rate limiting.
- `docs/` — документація проєкту (англійською), `CHANGELOG.md` і `ROADMAP.md` — у корені.
- Прочитай `frontend-react/README.md` перед першим кроком: там перелічені всі npm-скрипти й те,
  що робить кожен із семи job-ів CI.

## Правила роботи

1. **Гілка**: `claude/website-ui-ux-improvements-9hovnw`. Не пушити нікуди більше.
2. **Один крок = один коміт.** Повідомлення коміту — англійською, у стилі наявної історії
   (`feat(home): drive filters from the URL`). Не змішувати кроки в одному коміті.
3. **Після кожного кроку** прогнати в `frontend-react/`:
   ```bash
   npm run lint && npm run typecheck && npm run test && npm run build && npm run css:orphans
   ```
   Крок не вважається завершеним, поки все зелене.
4. **Візуальні baseline-и** (`npm run test:visual`) ганяються в контейнері й падатимуть на
   кожній зміні вигляду — це очікувано. Перезаписуй **точково**: `npm run test:visual:update -- -g "home"`.
   Ніколи не запускай `--update` без `-g`, поки не дійдеш до фінального кроку: він мовчки
   перезапише всі дев'ятнадцять знімків.
5. **Мова**: увесь код, коментарі, тексти інтерфейсу й документація — англійською. Цей план —
   єдиний файл українською.
6. **Стиль коментарів**: у цьому репозиторії коментарі пояснюють *чому*, а не *що*. Тримайся
   того самого тону — подивись `src/styles/ui.css.ts` або `src/App.tsx` як зразок.
7. **Нових рантайм-залежностей не додавати** без окремого питання. Усе нижче реалізовується на
   тому, що вже є в `package.json`.
8. **Тести пишуться разом із кодом**, не після. Кожен крок нижче має розділ «Тести» —
   це мінімум, не максимум.
9. Якщо якийсь крок виявиться помітно більшим, ніж описано, або впреться в те, чого план не
   передбачив, — зупинись і напиши про це, а не імпровізуй мовчки.

## Крок 1 — Фільтри живуть в URL

**Проблема.** `HomePage.tsx:31-33` тримає `search`, `tag` і `sort` у `useState`. Через це
неможливо поділитися посиланням на відфільтрований каталог, кнопка «назад» не повертає
попередній фільтр, а F5 скидає все до початкового стану.

**Файли**: `src/pages/HomePage.tsx`, `src/pages/homeInteractions.test.tsx`.

**Що зробити.**

Джерелом правди стає рядок запиту: `?q=<пошук>&tag=<тег>&sort=<az|za>`. Значення за
замовчуванням в URL **не потрапляють** — `/` і `/?sort=default` не повинні бути двома різними
адресами.

Поле пошуку лишається контрольованим локальним стейтом (`draft`), інакше воно лагатиме на
кожному натисканні клавіші. Синхронізація двостороння, обидва напрямки з охоронною умовою на
рівність — без неї ефекти зациклюються:

```ts
const [params, setParams] = useSearchParams();
const q = params.get("q") ?? "";
const [draft, setDraft] = useState(q);
const debounced = useDebounce(draft.trim(), 250);

// draft → URL: replace, щоб набір із десяти символів не породив десять записів в історії
useEffect(() => {
  if (debounced === q) return;
  setParams(next => { /* виставити або прибрати q */ }, { replace: true });
}, [debounced]);

// URL → draft: кнопка «назад», зовнішнє посилання, перезавантаження
useEffect(() => {
  setDraft(prev => (prev.trim() === q ? prev : q));
}, [q]);
```

Клік по тегу або зміна сортування — це **звичайна навігація** (`replace: false`), щоб «назад»
повертав попередній фільтр. Введення тексту — `replace: true`.

Валідація вхідних параметрів: `sort` поза множиною `default | az | za` ігнорується (падаємо на
`default`) і **вичищається з URL**, щоб `/?sort=%3Cscript%3E` не лишався в адресному рядку.
`tag`, якого немає в каталозі, лишаємо як є — бекенд просто поверне порожній список, і
користувач побачить порожній стан із назвою тегу.

Кнопка очищення пошуку прибирає і `draft`, і параметр `q`.

**Взаємодії, які мають працювати після кроку:**

| Дія | Очікуваний результат |
| --- | --- |
| Відкрити `/?q=sea&tag=cold&sort=az` | Поле пошуку заповнене, чіп `#cold` активний, сортування A-Z, грід відфільтрований |
| Набрати «sea» (3 символи) | Один запит до API через 250 мс, **один** новий запис в історії |
| Клікнути тег → «назад» | Повертається попередній тег, грід перемальовується |
| F5 на відфільтрованій сторінці | Стан збережений повністю |
| Скопіювати адресу й відкрити в іншій вкладці | Той самий вигляд |

**Тести** (`homeInteractions.test.tsx`): рендер у `MemoryRouter` з
`initialEntries={["/?q=sea&tag=cold"]}` — перевірити значення інпута, `aria-pressed` на чіпі й
параметри виклику API; клік по тегу — перевірити зміну URL; невалідний `sort` — перевірити
падіння на `default`.

**Коміт**: `feat(home): drive search, tag and sort from the URL`

## Крок 2 — Сторінка палітри `/p/:slug`

**Проблема.** Бекенд віддає `GET /api/v1/palettes/{slug}` (`backend/app/routers/palettes.py:41`),
і фронтенд не викликає цей ендпоінт **ніде**. Окремої палітри в інтерфейсі не існує: її не можна
відкрити, пошерити, показати в месенджері прев'ю. Це найбільша прогалина релізу — усі наступні
кроки на неї спираються.

**Нові файли**: `src/pages/PalettePage.tsx`, `src/pages/PalettePage.css.ts`,
`src/pages/PalettePage.test.tsx`.
**Змінені**: `src/api/palettes.ts`, `src/api/hooks.ts`, `src/api/queryKeys.ts`, `src/App.tsx`,
`src/components/PaletteCard.tsx`, `src/pages/HomePage.tsx`, `e2e/a11y.spec.ts`,
`e2e/visual/pages.spec.ts`.

**Шар даних.**

```ts
// api/palettes.ts
export function getPalette(slug: string): Promise<Palette> {
  return request<Palette>(`/palettes/${encodeURIComponent(slug)}`);
}

// api/queryKeys.ts
palette: (slug: string) => ["palette", slug] as const,

// api/hooks.ts
export function usePalette(slug: string) {
  return useQuery({ queryKey: queryKeys.palette(slug), queryFn: () => getPalette(slug), enabled: Boolean(slug) });
}
```

Перехід з картки на сторінку має бути миттєвим, а не з блимкою завантаження: у `usePalette`
підстав `initialData`, знайшовши палітру в уже закешованих списках через
`queryClient.getQueriesData({ queryKey: ["palettes"] })`. Разом із `initialDataUpdatedAt` це дає
миттєвий рендер і фонове оновлення. Якщо в кеші порожньо (прямий вхід за посиланням) — звичайне
завантаження.

**Маршрут**: `<Route path="p/:slug" element={<PalettePage />} />` всередині `<Layout />`,
підключений `lazy`, як усі інші, крім головної.

**Структура сторінки, згори вниз.**

1. **Повернення назад.** Посилання «← All palettes». Картка передає поточний рядок запиту через
   `state`, сторінка читає його: `to={`/${location.state?.from ?? ""}`}`. Так користувач
   повертається у **свій** відфільтрований каталог, а не на чисту головну. Якщо `state` порожній
   (прямий вхід) — на `/`.
2. **Заголовок**: `h1` з назвою, під ним опис, під ним теги — кожен як `Link` на `/?tag=<name>`.
3. **Головний блок кольорів.** Не смужка, як на картці, а великі блоки на всю ширину контейнера.
   У кожному блоці HEX видно **завжди** (не по наведенню), під ним — RGB і HSL меншим кеглем.
   Клік по блоку копіює HEX і показує тост. Текст поверх кольору фарбується в чорний або білий
   залежно від його яскравості — використай наявний `getRelativeLuminance` з `lib/color.ts`
   (поріг 0.5), інакше на світлих кольорах підпис зникне.
4. **Ряд дій**: `Save` / `Saved` (та сама логіка, що на картці), `Copy all` (усі HEX через кому),
   `Copy CSS` (через наявний `generateExportText`), `Share` (копіює канонічний
   `window.location.href` і показує тост «Link copied»).
5. **Матриця контрастів.** Таблиця N×N (N ≤ 8 за схемою бекенда), у клітинці — коефіцієнт
   контрасту пари й позначка `AAA` / `AA` / `—`. Діагональ порожня. Це і є пояснення до бейджа з
   картки, який досі не казав, між якими саме кольорами рахує. Обов'язково `<table>` із
   `<caption>` і `scope` на заголовках — це дані, а не декорація, і зчитувач має їх прочитати.
   Логіку винеси в `lib/color.ts` як `getContrastMatrix(colors: string[])` з юніт-тестами.
6. **Схожі палітри.** Запит `usePalettes({ tag: <перший тег>, limit: 4 })`, виключити поточну,
   показати до трьох карток. Якщо тегів немає або результат порожній — секцію не рендерити
   взагалі (не показувати порожній стан).

**Стан 404.** Якщо запит впав з `ApiError` і `status === 404` — рендерити `EmptyState` із
заголовком «Palette not found», текстом «This palette may have been renamed or removed.» і
кнопкою на `/`. Не показувати загальну помилку мережі — це різні речі для користувача.

**Зв'язок картка → сторінка.** У `PaletteCard.tsx` посиланням стає **лише заголовок**:

```tsx
<h3 className={styles.title}>
  <Link to={`/p/${palette.slug}`} state={{ from: location.search }}>{palette.name}</Link>
</h3>
```

Всю картку в `<Link>` **не загортати**: усередині вже є кнопки (свотчі, Save), а вкладені
інтерактивні елементи ламають і клавіатуру, і зчитувачі екрана. Якщо хочеться більшої зони
натискання — розтягни псевдоелемент посилання на картку (`::after` з `position: absolute`), а
кнопкам додай `position: relative; z-index: 1`, щоб вони лишалися клікабельними поверх нього.

**Кнопка «Random palette» переїжджає сюди.** Зараз (`HomePage.tsx:54-63`) вона не показує
випадкову палітру, а вписує її назву в поле пошуку й фільтрує грід — та ще й вибирає з уже
відфільтрованого набору. Замінити на `navigate('/p/' + випадковий slug)`. Якщо список порожній —
кнопка `disabled`.

**Тести.** `PalettePage.test.tsx`: рендер із замоканим API — назва, опис, теги, кількість блоків
кольорів; клік по блоку викликає буфер обміну й тост; відповідь 404 дає стан «Palette not
found»; посилання «назад» несе за собою рядок запиту. Плюс юніт-тести `getContrastMatrix` у
`lib/color.test.ts`.
**E2E**: додати `/p/<slug>` до `e2e/a11y.spec.ts` (нуль порушень axe) і новий знімок
`palette-detail` до `e2e/visual/pages.spec.ts`.

**Коміт**: `feat(palettes): add a shareable palette page at /p/:slug`

## Крок 3 — Пагінація замість мовчазного обрізання

**Проблема.** `HomePage.tsx:50` жорстко просить `limit: 100`, а `total`, який бекенд чесно
повертає, ніде не читається. Щойно палітр стане більше ста — решта зникне без жодного натяку.
Те саме на сторінці Export (`limit: 200`).

**Файли**: `src/api/hooks.ts`, `src/pages/HomePage.tsx`, `src/pages/HomePage.css.ts`,
`src/pages/ExportPage.tsx`.

**Що зробити.**

Додати `usePalettesInfinite` на `useInfiniteQuery`:

```ts
getNextPageParam: (last) =>
  last.offset + last.items.length < last.total ? last.offset + last.limit : undefined,
```

Сторінка — 24 палітри (кратно трьом колонкам гріда, тож останній ряд не рваний). Ключ запиту
містить фільтри, тому зміна фільтра природно скидає пагінацію — окремої логіки скидання не
треба.

**Кнопка «Load more», а не нескінченний скрол.** Нескінченний скрол ламає футер, погано працює з
клавіатури й псує CLS, який у цьому проєкті вже вимірювали. Кнопка чесніша.

Під гридом:
- лічильник `Showing 24 of 137 palettes` (замінює теперішній `137 palettes`);
- кнопка `Load more` — прихована, коли `hasNextPage === false`; напис `Loading…` і `disabled`,
  поки `isFetchingNextPage`.

**Керування фокусом.** Після довантаження фокус лишається на кнопці (вона не зникає) — це
правильно, але зчитувач не дізнається, що щось з'явилося. Тому лічильник уже має
`aria-live="polite"`: онови його текст **після** приходу даних, і зміна «Showing 24 of 137» →
«Showing 48 of 137» буде оголошена. Нічого фокусувати примусово не треба.

**Export.** Замінити `usePalettes({ limit: 200 })` з клієнтською фільтрацією на серверний пошук:
`usePalettes({ search: query, limit: 8 })`. Тоді підбірник ніколи не бреше про те, що «нічого не
знайдено», лише тому, що потрібна палітра не влізла в перші 200. Функцію `matches()` і
`defaultSample` після цього прибрати (для порожнього запиту лишити `usePalettes({ limit: 3 })`).

**Тести**: мок API з `total: 30`, `limit: 24` — перевірити наявність кнопки, клік, доклеювання
другої сторінки, зникнення кнопки; при `total: 10` кнопки немає.

**Коміт**: `feat(home): paginate the palette grid instead of capping it at 100`

## Крок 4 — Теги за популярністю, а не навмання

**Проблема.** `pickRandom` у `HomePage.tsx:37-44` перетасовує чіпи на кожен перерахунок `tags`.
Це не лише неспокійно виглядає — це **баг стану**: якщо вибраний тег не потрапив у нові десять
випадкових, фільтр зникає з інтерфейсу, але лишається застосованим. Користувач бачить неповний
список і не розуміє чому. Водночас у типі `Tag` є поле `count`, яке ніде не використовується.

**Файли**: `src/pages/HomePage.tsx`, `src/pages/HomePage.css.ts`.

**Що зробити.**

1. Прибрати `pickRandom` повністю. Чіпи — це топ-10 тегів за `count`, спадно; при рівному
   `count` — за алфавітом, щоб порядок був детермінований між рендерами.
2. Вибраний тег **завжди** присутній у ряду, навіть якщо він поза топ-10: якщо його там немає,
   додати одинадцятим. Це та умова, що прибирає баг.
3. У чіпі показати кількість: `#cold · 12`. Число робить фільтр передбачуваним — видно, скільки
   буде результатів.
4. Кнопка `More tags` у кінці ряду розгортає повний список (`aria-expanded`, `aria-controls`,
   контейнер `hidden` доти). Не робити модалку — наявний `ModalProvider` уміє лише
   confirm/prompt, і розширювати його API заради списку тегів невиправдано.
5. Теги з `kind === "purpose"` (їх десять, засіяні при першому запуску) виділити тонко — інша
   рамка або крапка перед назвою. Не кольором: колір у цьому застосунку означає дані.

**Тести**: мок `useTags` з різними `count` — перевірити порядок; вибраний тег поза топ-10
присутній у документі; `More tags` перемикає `aria-expanded`.

**Коміт**: `feat(home): rank tag chips by usage and keep the active one visible`

## Крок 5 — Головний екран говорить про продукт

**Проблема.** Дві окремі речі.

По-перше, герой з'їдає весь перший екран: на 1280×800 не видно жодної палітри без скролу, при
тому що палітри і є продукт. Винен глобальний `h1` з `fontSize: clamp(2.4rem, 6vw, 5rem)`
(`global.css.ts:100`).

По-друге, підзаголовок героя (`HomePage.tsx:71-75`) — це нотатка релізу:
*«This release watches your session: if a stolen sign-in is ever replayed, every device is signed
out at once»*. Відвідувачу сайту про кольори вона не говорить нічого. Такий текст належить
`/changelog`.

**Файли**: `src/styles/global.css.ts`, `src/pages/HomePage.tsx`, `src/pages/HomePage.css.ts`,
`src/pages/FavoritesPage.tsx`, `src/pages/ExportPage.tsx`, `src/components/Layout.tsx`.

**Що зробити.**

1. `h1`: `clamp(2.2rem, 4.5vw, 3.6rem)`. Правило глобальне, тож зачепить усі сторінки — це
   навмисно, вони всі надто великі. Візуальні baseline-и доведеться перезаписати для кожної

користувачів працює саме так.

Це найризикованіший крок релізу — він чіпає кожен `*.css.ts`. Роби його **після** кроків 1-7,

**Що зробити.**

   лише збільшена непрозорість або тонка світла рамка.

2. **Замінити всі захардкоджені світлі значення на токени.** Ось повний перелік, знайдений
   `grep`-ом — пройдись по кожному:

   | Файл | Рядки |

   (під картками просвічує градієнт фону).

3. **Оголосити темну тему.** `createGlobalTheme` не можна вкласти в media query, тож потрібні дві
   декларації:

   ```ts
   const dark = { /* значення */ };
   createGlobalTheme("[data-theme='dark']", vars, dark);          // явний вибір
   globalStyle(":root:not([data-theme='light'])", {                // системна умова

4. **Значення темної палітри** (відправна точка, звіряй контраст після застосування):

   surfaceGlass  rgba(28, 26, 24, 0.78)
   surfaceStrong #262320
   text          #f2ede6
   muted         #a89e93
   border        rgba(242, 237, 230, 0.14)
   primary       #f2ede6
   onPrimary     #1c1a18
   primarySoft   #33302c
   danger        #e0736f
   success       #6fbf7a
   ```

5. **Перемикач.** Три стани: `System / Light / Dark`, у хедері поруч із навігацією. Зберігати в

6. **Спалах світлої теми до старту React** усувається скриптом у `<head>`, який ставить

7. `index.html`: додати `<meta name="color-scheme" content="light dark">`; оновити застарілий

## Свідомо поза межами v5.0

Не роби цього в цьому релізі, навіть якщо здасться доречним — запиши в `ROADMAP.md` як
відкладене:

- **Пошук за кольором** («знайди палітри, близькі до `#3B6FD4`»). Чесна реалізація — ΔE в OKLab
  на боці бекенда з індексом; клієнтська по перших 500 палітрах буде брехати на зростанні бази.
  Це окремий реліз із міграцією.
- **Гарячі клавіші** (`/` — пошук, `r` — випадкова, `?` — довідка). Дешево, але потребує
  акуратного глобального обробника, що мовчить у полях вводу, і власного діалогу довідки.
- **«Нещодавно переглянуті»** в `localStorage`.
- **Прев'ю палітри в макеті UI** (фейкова кнопка/картка/графік у кольорах палітри).
- **OG-зображення для сторінки палітри.** Потребує серверного рендера або окремого ендпоінта —
  SPA сама метатеги для кравлерів не віддасть. Разом з рештою SEO це окрема робота.

4, 6, 7, 9, 10 — те, що робить його завершеним. Кроки 8 і 11 можна віддати в 5.1, але тоді
назви реліз чесно й не обіцяй темну тему в чейнджлозі.
