Branch: release/5.2.8, based on the local 5.2.7 head 0bc2730.
Publication or merge of 5.2.7 on GitHub has not been verified.

Implemented:
- Export selection summary and Change action, Image/Code groups, SVG/PNG preview,
  contextual downloads/copy, generation errors and MIME types; URL history preserves context.
- Shared colors-first editor with live preview, stable row IDs, accessible reordering,
  inline validation and API-aligned optional description.

  The application now uses a data router; the route definitions remain in App.
- Separate nonmodal admin editor with focus return, compact list, preserved search/pagination,
  guarded tab/record changes, deletion pagination correction and pending operation feedback.
- README, changelog, footer and backend version metadata updated to 5.2.8.

- Full Vitest run: 236 tests in 43 files passed before final small refinements.

- New tests cover reordering an invalid HEX without losing its row identity, blocking invalid
  submission, optional description, Stay/Discard navigation and returning to a clean state.
- jsdom logged its unimplemented window.scrollTo method during admin focus/scroll restoration.

## Verification in the publishing environment (2026-09-16)

Performed in the session that imported the reviewed 5.2.8 commits and opened the PR. 5.2.7 is
already merged into `main` (PR #139), so `release/5.2.8` was branched from the current `main`
and the two 5.2.8 commits were cherry-picked onto it: `1d68361` (export/editor/admin/README)
then `d095fb9` (the 20px export-actions spacing). The delta versus `main` is 20 files,
+1080/-291 — matching the handoff. The 20px `marginBottom` on `panelActions` in
`ExportPage.css.ts` is present.

Frontend (Node 22, `npm ci`):

- `npm run build` (tsc + vite): passed.
- `npm run lint` (oxlint) and `npm run format:check` (prettier): passed.
- `npx vitest run --coverage --maxWorkers=2`: **237 passed / 43 files**, exit 0. Coverage —
  statements 79.45%, branches 73.41%, functions 74.64%, lines 81.75% (thresholds met). This
  completes the full-suite run of all 237 that the source environment had not confirmed.
- `npm run css:orphans`: no orphaned class names.
- The jsdom `window.scrollTo` "Not implemented" log appears during the editor/admin tests, as
  documented above; it is not a failure.

Backend (venv from `backend/requirements-dev.txt`, against a locally provisioned PostgreSQL 16
with `pg_trgm` — the Docker Compose `test` profile could not run because the egress policy
blocks the container image registry):

- `ruff check`, `ruff format --check`, `mypy backend/app`: passed.
- `pytest`: **192 passed**, coverage 88.92% (gate 80%). Unchanged from 5.2.7 — 5.2.8 only bumps
  the backend version metadata (`5.2.7` → `5.2.8` in `main.py`); no business logic changed.
- Alembic agreement (drop schema → `alembic upgrade head` → `alembic check`): "No new upgrade
  operations detected." `pip-audit --strict`: no known vulnerabilities.

Playwright:

- `e2e/` (a11y + flows + focus + email links): **32 passed** in the pinned-version browser. One
  real accessibility regression in the imported code was found and fixed: the editor's live
  preview was `<div aria-label="Live palette preview">` with no role, which axe flags as a
  serious `aria-prohibited-attr` on `/palettes/new`. Fixed by adding `role="img"` (a graphical
  colour strip) — accessible name preserved, no visual change. This is a deviation from the
  reference, committed separately.
- Visual baselines: the 5.2.8 export/admin/editor redesigns (and the changelog entry) changed
  six pages, so their baselines were re-recorded in the pinned Playwright image
  (`mcr.microsoft.com/playwright:v1.62.1-noble`) and a clean compare passes (22/22). The other
  16 baselines — carried forward from the 5.2.7 regeneration already on `main` — are unchanged.

Not verified here: the real-stack integration suite and the Lighthouse budget were left for CI
(they need container images the egress policy blocks; CI runs them on the PR). No manual
browser inspection of the 320/360/390/768/1024/1440 mobile/desktop widths or of light/dark by
eye was possible in this session (no browser display, and the live site host is egress-blocked);
the automated a11y and single-width visual suites are the coverage that ran.

Deviations from the reference `d095fb9`, each a separate commit:
1. `role="img"` a11y fix on the editor live preview (above).
2. Re-recorded visual baselines for the six 5.2.8 pages.
3. An integration-spec update — the 5.2.8 admin opens the create form in a separate non-modal
   panel, so `e2e/integration/stack.spec.ts` now clicks "New palette" before filling the name
   (CI's real-stack integration job failed on the old inline-form assumption; the same
   "New palette" → "Create palette" flow is what `AdminPage.test.tsx` already exercises). The
   integration job could not be run locally (its Compose stack needs container images the egress
   policy blocks).
4. A requested UI consistency change: the Export "Image / Code" segmented toggle now uses a
   sliding highlight (an absolutely-positioned indicator that translates with `transform 240ms
   cubic-bezier(0.22,1,0.36,1)`, disabled under `prefers-reduced-motion`), matching the theme
   toggle and the admin tabs, instead of snapping the active button's background. The export
   visual baseline was re-recorded for it.

All other code is the reference 5.2.8 verbatim.
